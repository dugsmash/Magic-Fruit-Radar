### 第十一轮（2026-08-29 04:05，v0.2.3）—— 修复许愿单开关闪退 + 彩虹字动画重置
1. **问题**：添加许愿单后点击「取消到货提醒」开关有概率闪退，同时文字变色/动画重置
2. **根因**：
   - onBindViewHolder 先 setChecked 后设监听器 → 复用的 ViewHolder 上残留的旧监听器在绑定期间被触发，回调里再调 refresh() → notifyDataSetChanged()，在 RecyclerView 布局计算中执行 → 闪退（概率取决于是否发生视图复用）
   - 开关回调里调用 refresh() 全量重绑 → 每行 startFlow() 从 0 重启 → 彩虹动画重置、瞬间变色
3. **修复**：
   - 绑定前先 setOnCheckedChangeListener(null) 再 setChecked，之后才挂新监听器（消除复用监听器误触）
   - 开关回调只原地更新该行 wishMeta 文案（盯梢中/已暂停），不再全量 refresh()
   - GradientTextView.startFlow() 增加保护：文字未变且动画运行中则保持当前进度继续流动（重绑不再重置）
4. **实测**：60 次快速切换 + 滚动触发 ViewHolder 复用 + 再切换 → 无闪退（进程存活、logcat 无 FATAL）；状态文案与开关/存储一致；两帧间隔 1.2s 像素对比 3.5% 差异 → 彩虹动画持续流动未冻结/重置
5. **版本**：versionCode 5 / versionName 0.2.3

### 真机测试发现并修复的 2 个 Bug

**① 货架永远 0 件：响应 data 包装层未解析（v0.2.5 修复）**

- **现象**：真实 API 返回 `{"code":0,"data":{"merchantActivities":[...9 件商品...],"random_goods":[...]}}`，但 App 货架显示「货架 0 件，命中许愿 0 件」
- **根因**：`MerchantResponse` 直接读顶层 `merchantActivities`/`random_goods`，未解析 `data` 包装层 → Gson 全部为 null
- **附带**：`random_goods` 字段实为 `goods_name`/`buy_limit_num`/`item_num`，`RandomGood` 未映射，兜底解析同样失效
- **修复**：`Models.kt` 新增 `MerchantData` 包装层，`MerchantResponse` 兼容 data/顶层两种结构；`RandomGood` 增加 `goods_name` 等字段映射；`MerchantRepository.flattenProducts` 改用 `displayName` 并补全价格/数量/图标字段
- **验证**：修复后真实拉取 → **「检测完成：货架 9 件，命中许愿 7 件」**，货架完整显示 9 件带图鉴图标，记录页自动写入 9 件记录

**② 「即将收摊」通知误报：缺少剩余时间校验（v0.2.5 修复）**

- **现象**：手动刷新后（本轮剩余 93 分钟）立即收到「远行商人 · 即将收摊 … 剩余不足 15 分钟」
- **根因**：`maybeUrgentNotify()` 被 `maybeAutoFetch()`（onResume 时）无条件调用，而「≤15 分钟」判断只在 `updateCountdown()` 内做，`maybeUrgentNotify()` 自身不校验剩余时间
- **修复**：`maybeUrgentNotify()` 入口增加剩余时间检查（>15 分钟直接 return）
- **验证**：修复后重新安装并回货架页，无新的「即将收摊」误报通知

**③ 货架混入全部轮次商品：未按当前时段过滤（v0.2.5 修复）**

- **现象**：货架与记录显示所有时段商品（如 12:00-16:00 轮次却显示 08:00-12:00 已结束的国王球/首领血脉秘药）
- **根因**：`MerchantChecker.finalize()` 中 `active` 过滤只用于匹配许愿单，**缓存（setCachedProducts）、记录（recordFetch）、返回值（CheckResult.products）全部用的未过滤全量商品**，导致跨轮次商品上架/下架后仍显示在货架并记入错误时段
- **修复**：`finalize()` 先按 `MerchantRepository.isActive(item, now)` 过滤出当前时段在售商品，再统一用于缓存、记录、通知匹配与返回
- **验证**：当前 12:00-16:00 轮次真实拉取 → **「检测完成：货架 7 件，命中许愿 7 件」**（淘沙球/残缺魔镜/适格钥匙/能力钥匙/奇异血脉秘药/武系粉尘/紫莲刚玉），国王球/首领血脉秘药不再显示；记录页同步为「7 件 · 时段：12:00-16:00」

## 十、手机后台可靠性专项（2026-08-29 16:00，v0.2.6）

> 问题：锁屏 / 切后台 / 重启手机后经常收不到到货提醒（后台检测被冻结或丢失）。
> 根因：① 无开机自恢复（`RECEIVE_BOOT_COMPLETED` 权限已声明但**没有注册接收器**，重启后调度全部丢失，必须手动打开 App 才恢复）；② 未申请「忽略电池优化」白名单（Doze 冻结定时任务与网络）；③ 一次性检测任务无自愈机制（进程被 ROM 清理/任务丢失后不再恢复）；④ 国产 ROM（MIUI/EMUI/ColorOS 等）后台杀进程，App 内无引导。

### 修复清单（v0.2.6，versionCode 8）

1. **开机/升级/改时区自动重排**：新增 `worker/BootReceiver.kt`，监听 `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `TIME_SET` / `TIMEZONE_CHANGED`，触发后重排「本轮检测 + 周期守护」——重启手机后无需打开 App 也能恢复后台提醒
2. **周期自愈守护**：新增 `worker/WatchdogWorker.kt`（每 30 分钟一次，`ExistingPeriodicWorkPolicy.KEEP` 幂等）：
   - 该轮（08/12/16/20 点 +5 分钟）到点仍未检测 → 立即补检一次（不浪费积分，仍受「每轮一次」限流）
   - 下一轮一次性任务不在队列（被清理/丢失）→ 重新排期
   - `WorkScheduler` 新增 `enqueueCheckNow()` / `hasPendingCheck()` / `ensureWatchdog()` / `nextCheckLabel()`
3. **电池优化白名单**：新增 `util/BatteryOptimizer.kt` + `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 权限：
   - 首次启动弹窗引导（仅一次，`Prefs.batteryGuideShown` 标记）→ `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
   - 设置页新增「后台运行保护」区：实时状态（电池白名单 ✅/⚠️ + 下次检测时刻 + 守护任务运行状态）+「🔋 忽略电池优化」按钮 +「📖 各品牌后台白名单指引」弹窗（小米/华为/OPPO/vivo/三星/原生）
4. **检测任务互相兜底**：`MerchantCheckWorker.doWork()` 完成后也 `ensureWatchdog()`（幂等）；设置页保存 / 打开 App 均重排任务
